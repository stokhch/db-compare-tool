# DB Compare — сравнение и копирование Oracle / PostgreSQL

Локальное веб-приложение (Node.js + Express, Vue 3 + DevExtreme) для:

- **сравнения схем**: Oracle ↔ Oracle, PostgreSQL ↔ PostgreSQL, Oracle ↔ PostgreSQL;
- **сравнения данных** построчно по ключу, с отчётом о расхождениях;
- **копирования баз** между машинами: перелив по соединениям (любые направления), `pg_dump`/`pg_restore`, Oracle Data Pump по сети, запуск **ora2pg**.

## Что взято из готовых проектов

| Идея | Откуда |
|---|---|
| Отчёт «объекты и количество строк с обеих сторон» (таблицы, индексы, PK/FK, последовательности, триггеры, представления, функции) | `ora2pg -t TEST` |
| Нормализация значений перед сравнением (числа, даты до микросекунд, UTC, CHAR, `''`/NULL), хранение истории сравнений | CrunchyData **pgCompare** |
| Потоковое сравнение без выгрузки таблиц в память, сравнение отсортированных по ключу потоков | **reladiff** / data-diff |
| Сравнение таблиц без ключа как мультимножеств строк | Google **DVT** (row hash) |
| Маппинг типов Oracle → PostgreSQL (NUMBER(p,0) → smallint/integer/bigint, DATE → timestamp(0), CLOB → text …) | **ora2pg** |
| Функции пакетов Oracle ищутся как `пакет_функция` (plsql2pg) и `пакет.функция` (ora2pg PACKAGE_AS_SCHEMA) | **plsql2pg**, **ora2pg** |
| Проверка кода PL/pgSQL расширением plpgsql_check в транзакции с откатом | **plsql2pg** (checker.py) |
| Допуск при сравнении чисел (абсолютный / относительный) | **plsql2pg** (verify.py) |
| Понятные подсказки к ошибкам подключения | **plsql2pg** (checker.py), расширено для Oracle |
| ora2pg из комплекта plsql2pg для Windows (Perl + ora2pg без установки) | **plsql2pg** |

ora2pg не переписан, а подключён как внешняя утилита: приложение собирает `ora2pg.conf` из сохранённых подключений и показывает результат.

## Установка (Windows)

1. Установите **Node.js 18+** (https://nodejs.org).
2. Распакуйте архив и запустите `start.bat`. При первом запуске ставятся зависимости и собирается интерфейс, затем открывается http://localhost:3700.

Вручную:
```bat
npm run setup     :: зависимости сервера и клиента + сборка интерфейса
npm start         :: http://localhost:3700
```
Порт меняется переменной `PORT`. По умолчанию сервер слушает только `127.0.0.1`. Чтобы открыть доступ из сети, задайте `HOST=0.0.0.0`, но учтите, что авторизации в приложении нет.

### Необязательные утилиты

| Нужно для | Что установить |
|---|---|
| Oracle 11g или старые парольные верификаторы | Oracle Instant Client. Путь к нему укажите в *Настройках* (включится Thick-режим). Oracle 12.1+ работает без клиента. |
| pg_dump / pg_restore | Клиент PostgreSQL той же или более новой версии, чем сервер. На Windows ищется автоматически в `C:\Program Files\PostgreSQL\*\bin`. |
| ora2pg | Проще всего — распакованный [plsql2pg-windows-x64.zip](https://github.com/stokhch/plsql2pg/releases/tag/windows-latest): в нём уже есть Perl и ora2pg. Укажите его папку в *Настройках* (по умолчанию проверяется `C:\plsql2pg`). Для действий с подключением к Oracle Perl нужен ещё драйвер `DBD::Oracle` — его наличие видно в *Настройках*. Либо своя установка: Strawberry Perl + `DBD::Oracle` + `DBD::Pg` + ora2pg. |
| Проверка кода PostgreSQL | Расширение [plpgsql_check](https://github.com/okbob/plpgsql_check) на сервере PostgreSQL. Подключать его к базе не обязательно: на время проверки оно создаётся в транзакции с откатом (нужны права на CREATE EXTENSION). |
| Data Pump | Ничего ставить не нужно: импорт запускается PL/SQL-пакетом `DBMS_DATAPUMP` на сервере-приёмнике. |

### DevExtreme
Без лицензионного ключа DevExtreme 25.x показывает баннер «For evaluation purposes only». Ключ вашей компании положите в `client/.env` (`VITE_DEVEXTREME_LICENSE=…`, образец лежит в `client/.env.example`) и пересоберите интерфейс командой `npm run build`.

## Как пользоваться

1. **Подключения**: добавьте базы. Для Oracle можно указать service name, SID или полную строку (EZConnect или TNS-дескриптор). Пароли хранятся в `data/connections.json` в зашифрованном виде (AES-256-GCM). Ключ лежит в `data/.secret`, его можно задать переменной `DBCOMPARE_SECRET`.
2. **Сравнение схем**: выберите источник и приёмник со схемами и нажмите «Сравнить». Для баз PostgreSQL код функций, процедур и триггеров дополнительно проверяется через plpgsql_check: это аналог INVALID-объектов Oracle, который показывает, например, ссылки на несуществующие колонки. Результат группируется по категориям, кликом по категории включается фильтр. Отчёт можно открыть в HTML и отправить коллегам.
   - **Выбранные объекты**: переключатель «выбранные объекты» показывает список объектов схемы. Его можно отфильтровать по подстроке в имени, а кнопкой «Добавить связанные» дополнить выбор зависимостями: от чего зависят выбранные объекты (родительские таблицы по FK, таблицы представлений и кода, функции триггеров, последовательности), что зависит от них, или и то и другое, в том числе рекурсивно. Зависимости берутся из словаря: в Oracle из `ALL_DEPENDENCIES` и ограничений, в PostgreSQL из `pg_depend`, ограничений и триггеров, а зависимости кода PostgreSQL ищутся по тексту функций.
   - **Скрипт синхронизации структуры**, как «Schema Compare → migrate» в DBeaver. Он генерирует операторы, которые приводят приёмник к источнику: создание таблиц, добавление колонок, смену типов, NOT NULL, ключи, индексы и последовательности. Для одинаковых СУБД добавляется ещё DDL представлений, функций, пакетов и триггеров (`pg_get_*def` / `DBMS_METADATA`). У каждого оператора указан уровень риска. Удаление лишних объектов по умолчанию выключено. Нужные операторы можно отметить, скачать как `.sql`, скопировать или выполнить на приёмнике. В PostgreSQL выполнение идёт в одной транзакции и откатывается при ошибке.
3. **Сравнение данных**: загрузите список общих таблиц, при необходимости выберите нужные, задайте ключ и условие WHERE. В результате по каждой таблице видно, сколько строк отсутствует, сколько лишних и сколько отличается. Примеры отличий показаны с точностью до колонки. Кнопка «Добавить связанные таблицы» добавляет к выбору родительские и (или) дочерние таблицы по FK.
   - **Скрипт синхронизации данных** генерирует INSERT для отсутствующих строк, UPDATE только для отличающихся колонок и, по желанию, DELETE для лишних строк. Скрипт строится потоком во время повторного сравнения, поэтому подходит и для больших таблиц. Порядок учитывает внешние ключи: вставки идут от родительских таблиц к дочерним, удаления — в обратном порядке. Литералы формируются под диалект приёмника (TO_DATE, TO_TIMESTAMP, HEXTORAW, TO_CLOB, bytea и т. д.). Скрипт можно скачать или сразу выполнить: в PostgreSQL в одной транзакции, в Oracle с фиксацией пачками по 1000 операторов. В таблицах без ключа лишние строки скриптом не удаляются. BLOB больше 2000 байт в Oracle не помещаются в литерал, для них используйте перелив.
4. **Копирование**: на вкладке выберите способ.
   - *Перелив таблиц*: Oracle⇄PG в любую сторону. Отсутствующие таблицы создаются с маппингом типов, данные загружаются в порядке FK, на время загрузки можно отключить FK, после загрузки выравниваются последовательности. Код (PL/SQL) этим способом не переносится.
   - *pg_dump / pg_restore*: дамп и восстановление, только дамп или восстановление из сохранённого файла. Дампы лежат в `data/dumps`, их можно скачать.
   - *Oracle Data Pump*: сетевой импорт через DB link (аналог `impdp NETWORK_LINK`) с переименованием схемы. Кнопка «Команды expdp/impdp» генерирует команды для варианта через файлы.
   - *ora2pg*: SHOW_REPORT (оценка миграции), выгрузка DDL и кода, COPY, а также проверки TEST / TEST_COUNT / TEST_DATA.
5. **Задачи**: история всех запусков с журналом, отчётами и экспортом в JSON. Долгие задачи можно отменить.

## Миграция и проверка результата

| Раздел | Что делает |
|---|---|
| **Профиль данных** | Проверяет фактические значения колонок до выбора типов: дробные числа в «целых» колонках, время в DATE (можно ли `date`), `NUMBER` без точности с целыми значениями (`integer`/`bigint` вместо `numeric`), символ `\0` (PostgreSQL его не примет), пустые строки (`''` в Oracle = NULL), LONG, максимальные длины. С указанным приёмником проверяет и его фактические типы: переполнение, округление, потерю времени, усечение строк. |
| **Миграция → Конвейер** | Перенос одной кнопкой для репетиций: структура (таблицы без ключей) → данные в N потоков → PK, уникальные ключи, индексы, FK → последовательности → ANALYZE / DBMS_STATS → проверка (число строк, агрегаты или построчно). Время каждого шага и оценка окна простоя. Прерванный запуск можно продолжить: уже загруженные таблицы пропускаются. |
| **Миграция → Догрузка изменений** | Перед переключением переносит только изменения: по колонке даты изменения (вставка или обновление: `INSERT … ON CONFLICT` / `MERGE`) или по росту числового ключа. Удалённые строки находит сравнением одних ключей. |
| **Миграция → Права и окружение** | Из Oracle собирает роли и права (`GRANT`), комментарии, синонимы (→ представления или `search_path`), DB links (→ шаблоны `oracle_fdw`/`postgres_fdw`), задания `DBMS_SCHEDULER` (→ `pg_cron`, расписание переводится в cron). Операторы можно отметить, скачать или выполнить. |
| **Проверки → Сравнение запросов** | Один набор запросов выполняется в обеих базах. Сравниваются результаты (как наборы строк, по ключу или по порядку) и время. Медленные в PostgreSQL запросы отмечаются и получают `EXPLAIN`. Можно добавить все общие представления и топ запросов из `V$SQL` / `pg_stat_statements`. Наборы запросов сохраняются. |
| **Проверки → Сверка расчётов** | Шаги расчёта (`BEGIN pkg.proc; END;` / `CALL pkg_proc()`) выполняются в обеих базах, итоговые таблицы сравниваются в тех же сессиях, затем обе транзакции откатываются. CSV-файлы не нужны. |
| **Проверки → Сверка по агрегатам** | Для больших таблиц: COUNT, SUM/MIN/MAX чисел, диапазоны дат, суммарные длины строк и LOB — по таблице или по месяцам/годам. Затем построчно сравниваются только разошедшиеся группы. |
| **Код приложения** | Сканирует папку проекта (.js/.ts/.vue/.java/.cs/.py/.sql, XML-маппинги). Находит Oracle-конструкции в SQL-строках (NVL, DECODE, ROWNUM, `(+)`, CONNECT BY, `seq.NEXTVAL`, `:параметры` → `$1`, `MINUS`, `LISTAGG`, `''`/NULL…) и вызовы node-oracledb (`execute`, `executeMany`, OUT-параметры, `autoCommit`, `rowsAffected`, колонки ЗАГЛАВНЫМИ). Предлагает замену. Если указать базу Oracle, находит вызовы `пакет.процедура` и предлагает `пакет_процедура` (plsql2pg). Результат можно выгрузить в CSV. |
| **Регламент** | Наборы проверок на период параллельной работы. Проверка добавляется кнопкой «В регламент» на любом экране сравнения. Набор запускается вручную, по расписанию cron (пока приложение запущено) или командой `node server/cli.js suite "Имя"` из Планировщика заданий Windows (код возврата 0/1/2). Итог сравнивается с прошлым запуском, при расхождениях отправляется webhook (Teams, Slack, Mattermost). |

## Как сравниваются данные

- Обе выборки сортируются по ключу (PK, затем уникальный ключ, затем ключ, заданный вручную) и сравниваются потоком методом merge-join. Память не зависит от размера таблицы.
- Строковые ключи сортируются бинарно: в PostgreSQL через `COLLATE "C"`, в Oracle через `NLS_SORT=BINARY`. Если порядок в базах всё же различается (другая кодировка базы, разные типы ключа), приложение само переходит в режим хеш-таблицы: приёмник загружается в память.
- Нормализация значений:
  - числа приводятся к каноническому десятичному виду (`1.50` = `1.5`);
  - `boolean` сравнивается с `NUMBER(1)` как 1/0;
  - даты и время приводятся к `YYYY-MM-DD HH:MI:SS.ffffff` в UTC, Oracle DATE совпадает с `timestamp(0)`;
  - у CHAR обрезаются хвостовые пробелы;
  - пустая строка приравнивается к NULL (по умолчанию для пары Oracle⇄PG);
  - JSON сравнивается без учёта порядка ключей и пробелов, BLOB/bytea — по MD5.
- Допуск для чисел (как в plsql2pg verify): значения равны, если |a−b| ≤ абсолютного допуска или ≤ относительного × max(|a|,|b|). Строки, совпавшие только с учётом допуска, считаются отдельно («в допуске»). Для таблиц без ключа допуск не применяется.
- Таблица без ключа сравнивается как мультимножество хешей строк.

## Ограничения и что проверено

- **Проверено на живом PostgreSQL 16**: сравнение схем, сравнение данных во всех трёх режимах, перелив PG→PG с созданием таблиц (копия совпала с исходной на 100%), pg_dump/pg_restore. Логика нормализации и маппинга типов покрыта юнит-тестами: `node test/unit.test.js`.
- **Oracle-часть на реальном Oracle не запускалась**, потому что в среде разработки его не было. Сюда входят чтение метаданных, сравнение и перелив с участием Oracle, Data Pump. SQL написан для Oracle 12c+ по представлениям `ALL_*`. Первый запуск на Oracle сделайте на тестовой схеме.
- Сравнение схем Oracle⇄PG проверяет состав объектов и совместимость типов. Тексты процедур и CHECK-ограничений не сравниваются, потому что синтаксис в этих СУБД разный: для CHECK сравнивается их количество.
- Колонки INTERVAL при кросс-СУБД сравнении могут показываться как разные из-за формата.
- Перелив не переносит индексы (кроме PK), FK, CHECK, DEFAULT и код. Для полной миграции структуры используйте ora2pg (TABLE, VIEW, PACKAGE…) или Data Pump / pg_dump.
- В Data Pump по сети не переносятся таблицы с LONG / LONG RAW (ограничение Oracle).
- `session_replication_role = replica` (отключение FK в PostgreSQL) требует прав суперпользователя. Без них загрузка идёт в порядке зависимостей.

## Структура

```
server/
  index.js            REST API + раздача интерфейса
  db/                 адаптеры Oracle (node-oracledb) и PostgreSQL (pg)
  meta/               чтение метаданных в единую модель
  compare/schema.js   сравнение схем
  compare/data.js     сравнение данных (merge / map / multiset)
  copy/transfer.js    перелив таблиц
  copy/pgdump.js      pg_dump / pg_restore
  copy/datapump.js    Oracle Data Pump (DBMS_DATAPUMP, NETWORK_LINK)
  copy/ora2pg.js      обёртка ora2pg
  lib/                нормализация, маппинг типов, задачи, хранилище, отчёты
client/               Vue 3 + DevExtreme (Vite)
data/                 подключения, настройки, история задач, дампы (создаётся автоматически)
```

Режим разработки: `npm run dev` (сервер) и `npm --prefix client run dev` (интерфейс на :5173 с проксированием /api).
